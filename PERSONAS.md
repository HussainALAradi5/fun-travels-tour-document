# System Personas

These neutral role identifiers are used consistently in requirements, use cases, workflows, case studies, acceptance tests, and demonstrations.

| Identifier | Role | Goals | Typical permissions |
|---|---|---|---|
| Customer X | Prospective customer | Review public tours and create an account. | Public catalog, registration, and login |
| Customer Y | Existing customer | Reserve travel, select seats and meals, pay, manage tickets, and request support. | Own profile, bookings, wallet, notifications, and support requests |
| Employee X | Employee | Maintain daily tours, tickets, customers, and inventory. | Assigned agency and branch operations |
| Manager X | Manager | Approve workflows, manage inventory, and supervise employees. | Agency and branch operational approvals |
| Agency Owner X | Agency owner | Configure agencies, branches, staff, transport, meals, and offerings. | Owned agency resources |
| Administrator X | Administrator | Govern platform security, reference data, and exceptional operations. | Platform-wide administration |
| Support Agent X | Support agent | Triage, assign, discuss, resolve, and audit support requests. | Support queue and timelines |
| Developer X | Developer | Maintain typed integrations and reusable components. | Development-time responsibilities only |
| System Actor X | Automated system actor | Run reminders, cleanup, lifecycle processing, and maintenance. | Restricted internal service operations |

These identifiers are not personal names, production accounts, or test credentials.
