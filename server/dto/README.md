# DTOs

Every request and response body is a Java record in `dto/<domain>/`, one type per file. Entities never cross the API boundary.

- Requests carry Bean Validation annotations; a compact constructor may normalize input before validation (mobile numbers drop spaces and a leading 00).
- Responses are built by a static `from(entity)` factory next to their shape; there is no mapper class. Nested references use shared summary records (`UserSummary`, `CountrySummary`, `TourSummary`, ...).
- Filter DTOs stay classes because they inherit the shared paging fields of `GenericFilterRequest` and are bound from the query string.
- The web client and the mobile app mirror these as `src/dtos/<domain>/<Name>Dto.ts`, generated by `tools/generate-ts-dtos.py`; rerun it after changing a DTO.
